# Internet Checker

Кросплатформенная утилита для Windows и Linux, которая отслеживает:

- доступность интернета (`online/offline`);
- страну подключения (удобно для контроля VPN/маршрутизации);
- доступность нужных сайтов и сервисов отдельными проверками.

В меню и подсказке иконки показаны только сервисы с подтверждённым статусом `OFFLINE`. Доступные сервисы и сервисы без результата проверки скрыты. При доступности всех сервисов остаются страна подключения и время обновления.

Иконка в трее — тёмно-зелёный круг с белой галочкой, когда интернет и все настроенные сервисы доступны. Если хотя бы одна проверка не подтвердила доступность или возникла ошибка, показан красный крестик ❌. До первого результата используется крестик; во время очередной проверки сохраняется последний результат. Иконка обновляется автоматически, включая изменение доступности OpenAI API.

Пункт меню **«Использование сети…»** открывает подробную статистику трафика самого Internet Checker. В меню также показаны общий расход за запуск и средняя скорость за последнюю минуту. Учёт использует уже выполняемые проверки и не отправляет дополнительных запросов.

В окне доступны объёмы приёма и отправки, скорость за минуту и за запуск, пик секундного учёта, прогноз расхода за час и сутки при текущем темпе, количество успешных и неуспешных попыток, таймаутов, редиректов и одновременно выполняемых проверок. Таблица ресурсов показывает вклад каждого адреса в расход, среднее и максимальное время проверки, P95 по последним 200 попыткам. Выбор строки раскрывает тела запросов и ответов, оценку заголовков и расход на одну попытку. На вкладке истории показаны ежедневные объёмы и разбивка по адресам; историю можно сохранить в CSV.

Прочитанные HTTP-тела учитываются до распаковки через [`HTTPResponse.tell()`](https://urllib3.readthedocs.io/en/stable/reference/urllib3.response.html#urllib3.response.HTTPResponse.tell); заголовки оценены по их длине. Для MTProto учитываются отправленные и полученные данные протокола. TLS, DNS, обмен с прокси, TCP/IP, повторные передачи и непрочитанные данные в сокете не учитываются. При ошибке до получения ответа полный расход определить нельзя. Поэтому итог помечен знаком `≈`: фактический расход соединения может быть выше. Скорость и пик рассчитаны по времени завершения проверок, а не по моменту прихода каждого пакета.

История хранится в `network-metrics.json` в пользовательском каталоге приложения не более 30 дней и сохраняется каждые 30 секунд и при обычном выходе. В ней есть только счётчики, категории и имена ресурсов; содержимое запросов, ответов и ключи API не сохраняются. Счётчики текущего запуска начинаются заново после перезапуска, дневная история сохраняется.

Статус ChatGPT объединяет доступность сайта и `ab.chatgpt.com`, откуда приложение Codex/ChatGPT получает конфигурацию при запуске. Для `ab.chatgpt.com` проверяется анонимный POST-запрос `/v1/initialize` с публичным клиентским ключом SDK: полный JSON-ответ с настройками должен поступить за **10 секунд**. Обычный GET этого адреса может вернуть 403 и для этой проверки не подходит. Недоступные части показаны в одной строке:

- `ChatGPT: ab.chatgpt.com OFFLINE` — инициализация недоступна;
- `ChatGPT: сайт OFFLINE` — сайт недоступен;
- `ChatGPT: сайт OFFLINE, ab.chatgpt.com OFFLINE` — обе части недоступны.

Успешная проверка подтверждает доступность запроса инициализации в момент проверки. Остальные запросы приложения и вход в аккаунт могут иметь собственные ошибки. Если приложение сменит клиентский ключ SDK или формат ответа, параметры этой проверки потребуется обновить.

Общий интернет проверяется HTTPS-запросами к нескольким независимым источникам с проверкой ожидаемого кода и содержимого ответа. Открытый TCP-порт, страница входа в Wi-Fi, редирект или ответ прокси с ошибкой не засчитываются. Результаты проверки страны и отдельных сервисов не повышают общий статус интернета. В меню при наличии связи первой строкой показана страна; при отсутствии — `Нет интернета`.

По умолчанию одна проверка интернета ждёт корректный ответ до 10 секунд. Статус `Нет интернета` появляется после двух последовательных неуспешных циклов; единичный таймаут при смене VPN не меняет последнее подтверждённое состояние. Успешная проверка сразу сбрасывает счётчик сбоев и подтверждает восстановление. Поэтому подтверждение настоящего отключения может занять примерно 25 секунд при стандартном интервале опроса. Ход подтверждения записывается в журнал.

Telegram Desktop проверяется по MTProto: отправляется начальный `req_pq_multi` и проверяется ответ `resPQ` с тем же случайным числом. Используются два стартовых адреса из [исходного кода Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/mtproto/mtproto_dc_options.cpp), лимит — 10 секунд. Вход в аккаунт не выполняется, обмен сообщениями не проверяется. Проверка использует системную маршрутизацию и настроенный HTTP/SOCKS-прокси; персональный прокси, заданный только внутри Telegram, и дата-центр конкретного аккаунта могут отличаться. [Описание начального обмена MTProto](https://core.telegram.org/mtproto/samples-auth_key).

По умолчанию приложение пытается работать в системном трее. Клик по иконке открывает меню со статусом, ручной проверкой, открытием лога и выходом. Если на Linux нет GUI-сессии или зависимостей для трея, приложение автоматически работает без трея.

## Возможности

- Режим трея по умолчанию (`python main.py`) при наличии GUI.
- Защита от запуска второй копии: Windows mutex, Linux/macOS lock-файл.
- Периодическая проверка сети с несколькими endpoint и повторами.
- Параллельные быстрые проверки сети, страны и настроенных сервисов.
- Уведомления о смене статуса сети и страны.
- Уведомление о непрерывном сбое показывается один раз. Состояние сохраняется в `notification-state.json` между запусками; успешная проверка ресурса разрешает уведомление о новом сбое. Общий сбой интернета не сбрасывает уведомления о продолжающихся сбоях сервисов.
- OpenAI API показан отдельной метрикой; уведомления о его недоступности не отправляются.
- По умолчанию уведомления о стране ограничены переходами, связанными с Россией.
- Ротация логов; при запуске удаляются файлы журналов, не обновлявшиеся более 30 дней.
- Runtime-файлы (`config.example.json`, `config.json`, `logs`) берутся из папки приложения, а при невозможности записи — из пользовательского каталога приложения.

## Требования

- Windows 10/11 или Linux
- Python 3.10+
- Для Linux-уведомлений: `notify-send` из `libnotify-bin`/`libnotify`.
- Для Linux-трея: установленный `tkinter`, доступная GUI-сессия (`DISPLAY` или `WAYLAND_DISPLAY`) и backend, поддерживаемый `pystray`.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Настройка

Создайте локальный конфиг из примера:

```powershell
Copy-Item config.example.json config.json
```

Linux:

```bash
cp config.example.json config.json
```

Если `config.json` отсутствует, приложение запускается со значениями по умолчанию.

### Проверка OpenAI API

Создайте `.env` из `.env.example` и укажите свой ключ:

```dotenv
OPENAI_API_KEY=
```

Ключ читается из `.env` в каталоге данных приложения либо из переменной окружения `OPENAI_API_KEY`. Переменная окружения имеет приоритет. Для запуска исходников каталог данных совпадает с папкой проекта; для EXE в автозагрузке Windows это `%LOCALAPPDATA%\InternetChecker`. При установке `install_startup.ps1` копирует локальный `.env` в этот каталог. Ключ не включается в EXE, пример настроек, журналы и Git.

Проверяется только [получение списка моделей — `GET https://api.openai.com/v1/models`](https://developers.openai.com/api/reference/resources/models/methods/list). Генерация не запускается, токены не расходуются. Проверка подтверждает соединение и возможность выполнить этот запрос с ключом; она не проверяет баланс, лимиты генерации или работоспособность конкретной модели. Редиректы не выполняются, чтобы ключ передавался только этому адресу. Лимит проверки — 10 секунд. API не влияет на статус ChatGPT или общего интернета и не вызывает уведомлений.

## Запуск

Обычный запуск (с иконкой в трее):

```powershell
python main.py
```

Запуск без трея (удобно для отладки в терминале):

```powershell
python main.py --no-tray
```

Один цикл проверки и выход:

```powershell
python main.py --once
```

Кастомный путь к конфигу:

```powershell
python main.py --config .\config.json
```

Linux-команды аналогичны, обычно через `python3`:

```bash
python3 main.py --no-tray
python3 main.py --once
python3 main.py --config ./config.json
```

## Установка в автозапуск

Этот способ относится к Windows.

Копирует standalone EXE прямо в папку Startup:

```powershell
powershell -ExecutionPolicy Bypass -File .\install_startup.ps1
```

Скрипт также останавливает старый процесс из Startup, удаляет устаревший `InternetChecker.lnk`, копирует `.env`, если он есть, и запускает новое приложение. Путь к файлу настроек API можно изменить через `-SourceEnvFile`.

## Ключевые параметры `config.json`

- `check_interval_seconds`, `request_timeout_seconds`, `connectivity_timeout_seconds`, `service_request_timeout_seconds`: интервал опроса и независимые таймауты определения страны (3 секунды), проверки интернета (10 секунд) и проверки сервисов (8 секунд, с переопределениями для отдельных сервисов). Таймауты поддерживают дробные значения.
- `connectivity_urls`, `connectivity_attempts`: источники и число попыток проверки интернета. Каждый источник содержит HTTPS-адрес `url`, `expected_status`, а для ответа с телом — `expected_body` или `must_contain`. Проверяются ожидаемый код и содержимое, TCP-подключения для общего статуса не используются. Общий лимит цикла учитывает число попыток.
- `connectivity_success_confirmations`, `connectivity_fail_confirmations`: число последовательных успешных или неуспешных циклов для изменения статуса интернета; по умолчанию 1 и 2.
- `country_lookup_urls`, `country_lookup_no_cache`: API и режим запрета кеша для гео-определения.
- `service_checks`, `service_success_confirmations`, `service_fail_confirmations`: отдельные HTTP-проверки (`GET`, `HEAD`, `POST`) и проверка Telegram (`MTPROTO`). `must_contain` проверяет маркер в ответе, `json` задает тело POST-запроса. Для сервиса `timeout_seconds` переопределяет таймаут, `fail_confirmations` — число неудачных проверок до `OFFLINE`, `notify` — уведомления. Для обеих частей ChatGPT, API и Telegram достаточно одной неудачной проверки. Части ChatGPT хранятся как `chatgpt` и `chatgpt-init`, но объединяются в меню и уведомлениях. У API задано `api_key_env: "OPENAI_API_KEY"`; для этой проверки разрешен только GET списка моделей, уведомления всегда отключены.
- `notify_only_russia_transitions`, `russia_country_codes`, `russia_country_names`: логика фильтрации уведомлений по РФ.
- `notify_on_service_status_change`: уведомлять ли о недоступности настроенных сервисов. Возврат сервиса в `ONLINE` отдельным уведомлением не показывается.
- `show_app_started_notification`, `app_started_title`, `app_started_message`: стартовое уведомление.
- `notification_cooldowns_seconds`, `dedup_window_seconds`: защита от спама уведомлениями.
- `single_instance_mutex_name`: имя Windows mutex и основа имени lock-файла на Linux/macOS.
- `log_file_path`, `log_max_bytes`, `log_backup_count`, `log_to_console`: параметры логирования.
- `tray_icon_tooltip`, `tray_show_status_label`, `tray_check_now_label`, `tray_open_log_label`, `tray_exit_label`: текст в трее.

Пример добавления сервиса:

```json
{
  "id": "example",
  "name": "Example",
  "probe_urls": [
    {
      "url": "https://example.com/",
      "method": "GET",
      "must_contain": "Example"
    }
  ]
}
```

В меню показаны страна или отсутствие интернета и отдельные строки сервисов. ChatGPT занимает одну строку с указанием недоступной части; API и Telegram имеют собственные строки. Уведомления перечисляют недоступные ресурсы, кроме API.
