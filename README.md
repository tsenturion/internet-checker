# Internet Checker

Internet Checker — приложение для Windows и Linux, которое следит за доступностью интернета, определяет страну подключения и проверяет нужные сайты и сервисы. Работает в системном трее, показывает сбои и уведомляет об изменениях. Страна подключения помогает контролировать маршрут через VPN.

[Скачать готовый EXE для Windows](https://github.com/tsenturion/internet-checker/releases/latest) · [Все выпуски](https://github.com/tsenturion/internet-checker/releases)

## Быстрый старт для Windows

1. Откройте страницу последнего выпуска и скачайте файл **InternetChecker.exe** из раздела **Assets**. Для готового EXE установка Python не требуется.
2. Поместите файл в отдельную папку с правом записи и запустите двойным щелчком. Иконка появится в области уведомлений рядом с часами; Windows может скрыть её под стрелкой.
3. Дождитесь первого результата и нажмите на иконку, чтобы увидеть страну подключения, недоступные сервисы и время обновления. Между общими циклами приложение по умолчанию ждёт 5 секунд; Нетология проверяется при запуске и затем раз в 30 минут либо вручную.
4. При необходимости настройте OpenAI API и автозапуск по инструкциям ниже. Остальные проверки работают без аккаунтов и ключей.

По умолчанию проверка OpenAI API включена и требует вашего ключа. Без него в меню появится `OpenAI API: ключ не указан`, а иконка останется красной. Можно добавить ключ или убрать проверку `openai-api` из списка `service_checks` в `config.json`.

## С какими ресурсами работает приложение

Ниже перечислены ресурсы из стандартных настроек в [config.example.json](config.example.json). Свой `config.json` позволяет изменить список адресов и добавить другие HTTP-сервисы.

### Проверяемые сервисы

| Ресурс | Адрес | Что проверяется |
| --- | --- | --- |
| ChatGPT — сайт | `https://chatgpt.com/` | GET главной страницы с маркером `ChatGPT` в ответе. |
| ChatGPT — инициализация | `https://ab.chatgpt.com/v1/initialize` | Анонимный POST с публичным клиентским ключом SDK; ожидается полный JSON с маркером `feature_gates` за 10 секунд. Параметры запроса заданы в конфигурации. |
| OpenAI API | `https://api.openai.com/v1/models` | GET списка моделей с вашим `OPENAI_API_KEY`; ожидается HTTP 200 и корректный список за 10 секунд. |
| Telegram Desktop | `149.154.167.51:443`, `149.154.167.91:443` | Начальный обмен MTProto; достаточно корректного ответа одного из адресов за 10 секунд. |
| Нетология (Netology) | `https://netology.ru/` | GET сайта раз в 30 минут или вручную; заглушки VPN/IP, отказа в доступе и ошибки `TypeError` считаются `OFFLINE` даже при HTTP 200. После 429 запросы прекращаются до перезапуска. |
| GitHub | `https://github.com/` | GET сайта с маркером `GitHub` в ответе. |

Сайт ChatGPT и его инициализация объединены в один статус **ChatGPT**. OpenAI API и Telegram Desktop отображаются отдельно. Доступность этих запросов подтверждает работу проверяемого адреса в данный момент; вход в аккаунт, отправка сообщений, генерация и другие действия пользователя не проверяются.

Для Telegram отправляется `req_pq_multi` и проверяется ответ `resPQ` с тем же случайным числом. Используются два стартовых адреса из [исходного кода Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/mtproto/mtproto_dc_options.cpp). Проверка учитывает маршрутизацию системы и HTTP/SOCKS-прокси из переменных окружения. Прокси, заданный только внутри Telegram, и дата-центр конкретного аккаунта могут отличаться. [Описание начального обмена MTProto](https://core.telegram.org/mtproto/samples-auth_key).

### Источники проверки интернета

| Источник | Адрес | Ожидаемый ответ |
| --- | --- | --- |
| Microsoft | `https://www.msftconnecttest.com/connecttest.txt` | HTTP 200 и текст `Microsoft Connect Test`. |
| Cloudflare | `https://www.cloudflare.com/cdn-cgi/trace` | HTTP 200 и строка `h=www.cloudflare.com`. |
| Google | `https://clients3.google.com/generate_204` | HTTP 204 без тела. |

Источники проверяются параллельно. Для подтверждения интернета достаточно одного корректного ответа. Открытый TCP-порт, страница входа в Wi-Fi, редирект или ответ прокси с ошибкой не засчитываются. Результаты определения страны и проверок отдельных сервисов не повышают общий статус интернета.

### Источники определения страны

| Источник | Адрес |
| --- | --- |
| ipwho.is | `https://ipwho.is/` |
| ip-api.com | `http://ip-api.com/json/?fields=status,country,countryCode,query` |
| ipapi.co | `https://ipapi.co/json/` |

Приложение использует первый полученный корректный ответ. Страна определяется по внешнему IP, видимому этому источнику, и может отличаться от маршрута отдельного сайта при раздельной маршрутизации VPN. Недоступность источников определения страны сама по себе не означает отсутствие интернета.

## Статусы и управление

| Что показано | Значение |
| --- | --- |
| Тёмно-зелёный круг с белой галочкой | Интернет и все настроенные сервисы доступны. |
| Красный крестик ❌ | Хотя бы одна проверка не подтвердила доступность, возникла ошибка или ещё нет первого результата. |
| Название страны | Интернет доступен; показана определённая страна подключения. |
| `Страна неизвестна` | Интернет доступен, но страну определить не удалось. |
| `Нет интернета` | Подтверждён общий сбой соединения. |
| Строка сервиса с `OFFLINE` | Подтверждён сбой этого сервиса. Доступные сервисы и сервисы без результата проверки скрыты. |

Во время очередной проверки иконка сохраняет последний результат. Когда все сервисы доступны, в строках статуса остаются страна подключения и время обновления.

В меню доступны команды:

- **Показать статус** — вывести текущее состояние уведомлением.
- **Проверить сейчас** — запустить очередной цикл без ожидания обычного интервала, включая Нетологию, если её проверки не остановлены после 429.
- **Использование сети…** — открыть статистику трафика Internet Checker.
- **Открыть лог** — открыть журнал для диагностики.
- **Выход** — остановить мониторинг и закрыть приложение.

ChatGPT указывает недоступную часть: `ChatGPT: сайт OFFLINE`, `ChatGPT: ab.chatgpt.com OFFLINE` или обе части в одной строке. Для инициализации используется POST; обычный GET этого адреса может вернуть 403. Если клиентский ключ SDK или формат ответа изменятся, параметры проверки потребуется обновить.

### Когда меняются статусы и приходят уведомления

Общая проверка интернета ждёт ответ до 10 секунд. Статус `Нет интернета` появляется после двух последовательных неуспешных циклов: единичный таймаут при смене VPN сохраняет последнее подтверждённое состояние. При стандартных настройках подтверждение отключения может занять около 25 секунд. Успешная проверка сразу подтверждает восстановление.

Для обеих частей ChatGPT, OpenAI API, Telegram и Нетологии по умолчанию достаточно одной неудачной проверки; для GitHub нужны три последовательных сбоя. Один успешный цикл подтверждает доступность сервиса.

Для Нетологии проверяется также текст HTML-ответа: сообщения «Кажется, у вас включён VPN или вы не в России» и «Извините, у вас нет доступа к данному контенту» означают отсутствие доступа. Страница «Извините, произошла ошибка» с `TypeError: Cannot read properties of undefined (reading 'length')` также считается недоступной. Правило действует для `netology.ru` и его поддоменов; учитываются HTML-сущности, неразрывные пробелы и разница между «ё» и «е». Сообщения внутри скриптов, стилей и комментариев не меняют статус. Причина отказа записывается в журнал.

Первая проверка Нетологии выполняется при запуске приложения, следующие — не чаще одного раза в 30 минут. Команда **«Проверить сейчас»** выполняет её сразу и отсчитывает следующие 30 минут заново. Между проверками сохраняется последний статус; пропущенные циклы не считаются новыми успехами или сбоями. Остальные сервисы продолжают проверяться в общем цикле.

При HTTP 429 или HTML-заглушке `429 Too Many Requests` Нетология сразу считается `OFFLINE`, а все её проверки, включая ручные, останавливаются до следующего перезапуска приложения. Ожидание 30 минут эту остановку не снимает. В меню и журнале показана причина. Остановка хранится только в памяти текущего запуска.

Уведомление о непрерывном сбое показывается один раз, в том числе после перезапуска приложения. Успешная проверка разрешает уведомление о следующем сбое. Общий сбой интернета не сбрасывает уведомления о продолжающихся сбоях сервисов. Восстановление отдельного сервиса не сопровождается уведомлением; уведомления о восстановлении интернета поддерживаются.

По умолчанию уведомления о смене страны показываются только при переходах, связанных с Россией. OpenAI API влияет на цвет иконки, но не вызывает уведомлений и не меняет статус ChatGPT или общего интернета.

## Проверка страны Office в Windows

При запуске Internet Checker один раз читает `CountryCode` из `HKCU\Software\Microsoft\Office\16.0\Common\ExperimentConfigs\Ecs`. Если значение указывает на Россию (`RU`), в меню трея появляется предупреждение. Результат чтения записывается в журнал. Если значение отсутствует или не распознано, страна считается неизвестной.

Проверка не изменяет реестр и не влияет на статус сети. Она показывает сохранённую настройку Office, а не страну текущего IP или доступность установщика. Чтобы перечитать значение, перезапустите Internet Checker.

## Настройки и файлы приложения

Приложение работает со стандартными настройками без `config.json`. При первом запуске оно создаёт `config.example.json` в каталоге данных. Чтобы изменить параметры, завершите приложение через **«Выход»**, скопируйте пример в `config.json`, отредактируйте его и запустите приложение снова.

| Способ запуска | Каталог данных |
| --- | --- |
| Готовый EXE в обычной папке | Папка с `InternetChecker.exe`, если она доступна для записи. |
| EXE в автозагрузке Windows или в папке без права записи | `%LOCALAPPDATA%\InternetChecker`. |
| Запуск из исходников | Папка проекта, если она доступна для записи. |
| Linux, если папка приложения недоступна для записи | `$XDG_CONFIG_HOME/internet-checker` или `~/.config/internet-checker`. |

В каталоге данных находятся:

- `config.example.json` — пример стандартных настроек; существующий файл автоматически не обновляется.
- `config.json` — ваши настройки, если вы их создали.
- `.env` — ключ OpenAI API, если он задан через файл.
- `logs/internet-checker.log` — журнал проверок и ошибок; путь можно изменить в настройках.
- `notification-state.json` — состояние уведомлений о продолжающихся сбоях.
- `network-metrics.json` — ежедневная история трафика за последние 30 дней.

Журнал ротируется по размеру. При запуске удаляются файлы журналов, не обновлявшиеся более 30 дней. История трафика сохраняется каждые 30 секунд и при обычном выходе. В истории есть счётчики, категории и имена ресурсов; содержимое запросов, ответов и ключи API не сохраняются.

### Ключ OpenAI API

Создайте в каталоге данных файл `.env` со строкой, заменив значение своим ключом:

```dotenv
OPENAI_API_KEY=ваш_ключ_API
```

При запуске из исходников можно скопировать [.env.example](.env.example) в `.env`. Переменная окружения `OPENAI_API_KEY` имеет приоритет над файлом. Для EXE в автозагрузке Windows нужен `%LOCALAPPDATA%\InternetChecker\.env`; скрипт установки копирует туда локальный `.env`, если он существует. Ключ не включается в EXE, пример настроек, журналы и Git.

Проверяется только [получение списка моделей — GET /v1/models](https://developers.openai.com/api/reference/resources/models/methods/list). Генерация не запускается, токены не расходуются. Проверка не определяет баланс, лимиты генерации или работоспособность конкретной модели. Редиректы отключены, чтобы ключ передавался только заданному адресу OpenAI API.

### Основные параметры `config.json`

| Параметр | Назначение и стандартное значение |
| --- | --- |
| `check_interval_seconds` | Пауза между циклами: 5 секунд. |
| `request_timeout_seconds` | Таймаут определения страны: 3 секунды. |
| `connectivity_timeout_seconds` | Таймаут проверки интернета: 10 секунд. |
| `service_request_timeout_seconds` | Общий таймаут сервиса: 8 секунд; у отдельных сервисов переопределён на 10 секунд. |
| `connectivity_success_confirmations`, `connectivity_fail_confirmations` | Число успешных и неуспешных циклов для смены статуса интернета: 1 и 2. |
| `service_success_confirmations`, `service_fail_confirmations` | Число успешных и неуспешных циклов для смены статуса сервиса: 1 и 3; возможны переопределения. |
| `notify_only_russia_transitions` | Уведомлять о смене страны только при переходах, связанных с Россией: `true`. |
| `notify_on_service_status_change` | Уведомлять о недоступности сервисов: `true`; для OpenAI API уведомления всегда отключены. |
| `show_app_started_notification` | Показывать уведомление о запуске: `true`. |

Таймауты поддерживают дробные значения. Параметры `connectivity_urls` и `connectivity_attempts` задают источники и число попыток проверки интернета; по умолчанию одна попытка. У каждого источника указываются `url`, `expected_status`, а для ответа с телом — `expected_body` или `must_contain`. Общий лимит цикла учитывает число попыток.

`country_lookup_urls` задаёт источники определения страны, `country_lookup_no_cache` — запрет кеширования. Фильтр уведомлений о России настраивается через `russia_country_codes` и `russia_country_names`.

`service_checks` содержит список сервисов. Поддерживаются HTTP-методы `GET`, `HEAD`, `POST` и метод `MTPROTO` для Telegram. `must_contain` задаёт маркер в ответе, `json` — тело POST-запроса. У сервиса `timeout_seconds` переопределяет таймаут, `fail_confirmations` — число сбоев до `OFFLINE`, `notify` — уведомления. Части ChatGPT имеют идентификаторы `chatgpt` и `chatgpt-init`. У OpenAI API задано `api_key_env: "OPENAI_API_KEY"`; для такой проверки разрешён только GET списка моделей.

Чтобы добавить сайт, включите следующий объект в массив `service_checks` вашего конфига. Заданный массив заменяет стандартный список целиком: сохраните в нём остальные нужные сервисы.

```json
{
  "id": "example",
  "name": "Мой сайт",
  "probe_urls": [
    {
      "url": "https://example.com/",
      "method": "GET",
      "must_contain": "Example"
    }
  ]
}
```

Параметры `app_started_title`, `app_started_message` задают текст стартового уведомления; `notification_cooldowns_seconds`, `dedup_window_seconds` ограничивают частоту уведомлений. Журнал настраивается через `log_file_path`, `log_max_bytes`, `log_backup_count`, `log_to_console`. Параметры `tray_icon_tooltip`, `tray_show_status_label`, `tray_check_now_label`, `tray_open_log_label`, `tray_exit_label` задают подписи в трее. `single_instance_mutex_name` определяет имя блокировки, защищающей от запуска второй копии.

## Статистика использования сети

Пункт **«Использование сети…»** показывает трафик самого Internet Checker. В меню также видны общий расход за запуск и средняя скорость за последнюю минуту. Учёт использует уже выполняемые проверки и не отправляет дополнительных запросов.

В окне доступны объёмы приёма и отправки, скорость за минуту и за запуск, пик секундного учёта, прогноз расхода за час и сутки при текущем темпе, количество успешных и неуспешных попыток, таймаутов, редиректов и одновременно выполняемых проверок. Таблица ресурсов показывает вклад каждого адреса в расход, среднее и максимальное время проверки, P95 по последним 200 попыткам — время, в которое уложились 95% попыток. Выбор строки раскрывает объёмы тел запросов и ответов, оценку заголовков и расход на одну попытку. На вкладке истории показаны ежедневные объёмы и разбивка по адресам; историю можно сохранить в CSV.

Итоги помечены знаком `≈`: учитываются прочитанные HTTP-тела до распаковки через `HTTPResponse.tell()`, оценка длины заголовков и данные обмена MTProto. TLS, DNS, обмен с прокси, TCP/IP, повторные передачи и непрочитанные данные в сокете не учитываются. При ошибке до получения ответа полный расход определить нельзя, поэтому фактический расход соединения может быть выше. Скорость и пик рассчитаны по времени завершения проверок. Счётчики текущего запуска начинаются заново после перезапуска; дневная история сохраняется.

## Автозапуск и обновление в Windows

Для установки готового EXE без исходников завершите приложение через **«Выход»**, нажмите `Win+R`, введите `shell:startup` и переместите туда `InternetChecker.exe`. Запустите его из этой папки. Приложение будет запускаться при входе текущего пользователя в Windows, а настройки и данные будут храниться в `%LOCALAPPDATA%\InternetChecker`. Если раньше EXE запускался из другой папки, перенесите нужные `config.json` и `.env` в новый каталог данных перед запуском.

При работе с исходниками можно воспользоваться скриптом из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\install_startup.ps1
```

По умолчанию скрипт берёт `dist\InternetChecker.exe`. Готовый скачанный файл можно указать через `-SourceExe`:

```powershell
powershell -ExecutionPolicy Bypass -File .\install_startup.ps1 -SourceExe "$env:USERPROFILE\Downloads\InternetChecker.exe"
```

Скрипт останавливает старый процесс из Startup, удаляет устаревший `InternetChecker.lnk`, копирует EXE в автозагрузку и запускает приложение. Он также копирует локальный `.env` в `%LOCALAPPDATA%\InternetChecker`; путь к исходному файлу ключа задаётся через `-SourceEnvFile`. `config.json` скрипт не переносит.

Для обновления завершите приложение и замените EXE в том же месте файлом из нового выпуска либо повторите установку скриптом. При сохранении каталога данных ваши настройки и история остаются на месте. Чтобы отключить автозапуск, завершите приложение и переместите EXE из папки `shell:startup` в обычную папку.

## Если что-то не работает

| Ситуация | Что проверить |
| --- | --- |
| Нет иконки в Windows | Раскройте скрытые значки рядом с часами. Второй запуск не создаёт вторую копию приложения. |
| Красная иконка при работающем интернете | Откройте меню: отдельный сервис может быть недоступен. Для строки `OpenAI API: ключ не указан` настройте ключ или уберите эту проверку из конфига. |
| После переключения VPN видна прежняя страна | Нажмите **«Проверить сейчас»** и дождитесь результата; проверьте маршрут и настройки прокси. |
| Настройки не применились | Проверьте каталог данных и корректность JSON, затем перезапустите приложение. Относительный путь `--config` отсчитывается от каталога данных. |
| Сайт доступен в браузере, но проверка не проходит | Браузер может использовать другой прокси, авторизованную сессию или проходить защиту сайта. В **«Открыть лог»** видны HTTP-коды, таймауты и другие причины отказа. |
| В Linux нет трея | Нужны GUI-сессия, `tkinter` и поддерживаемое `pystray` окружение. Если трей недоступен, приложение продолжает работу без него. |

## Запуск из исходников

Нужны Windows 10/11 или Linux и Python 3.10+. Для уведомлений Linux требуется `notify-send` из `libnotify-bin`/`libnotify`, для трея — `tkinter`, GUI-сессия (`DISPLAY` или `WAYLAND_DISPLAY`) и поддерживаемое `pystray` окружение.

Команды выполняются из папки проекта. Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 main.py
```

В Debian/Ubuntu при необходимости установите системные зависимости:

```bash
sudo apt install python3-tk libnotify-bin
```

Для изменения стандартных настроек скопируйте `config.example.json` в `config.json`:

```powershell
Copy-Item config.example.json config.json
```

В Linux используется `cp config.example.json config.json`. Дополнительные режимы запуска:

```powershell
python main.py --no-tray
python main.py --once
python main.py --config C:\InternetChecker\config.json
```

`--no-tray` запускает мониторинг в терминале; `--once` выполняет один цикл и завершает работу. В Linux команды аналогичны, обычно через `python3`; для конфига укажите путь Linux. Перед диагностическим запуском завершите уже работающую копию через **«Выход»**. Защита от второй копии использует mutex в Windows и файл блокировки в Linux.

## Сборка и выпуск для разработчиков

Сборка самостоятельного EXE для Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\build_exe.ps1
```

Результат — `dist\InternetChecker.exe`.

Процесс [release.yml](.github/workflows/release.yml) в GitHub Actions собирает EXE и публикует его в GitHub Release при отправке тега вида `vX.Y.Z`. Выпуск можно запустить вручную через **Actions → Release → Run workflow**, указав тег.
